# 既有企業網站 SEO／AI 搜尋更新

將既有企業形象網站升級為搜尋引擎與 AI 搜尋系統能正確理解的網站。這不是排名保證、關鍵字堆砌、假案例生成或付費廣告服務。

## 使用方式

使用者可直接說：

```text
請用既有企業網站 SEO／AI 搜尋更新模式，盤點並升級 [專案路徑]。先在本機完成，未經我同意不要發布。
```

開始時先讀取 [更新模式](references/更新模式.md)。

## 必守原則

- 先盤點、再提出可核對的更新清單；未取得內容與修改核准前，不改寫網站文案、不提交、不部署。
- 使用客戶已確認的服務、地區、資格、案例、地址、聯絡方式與圖片。缺漏資料標示待確認，不得以 AI 補造。
- SEO 與 AI 搜尋可見度共用同一基礎：清楚、可讀、對人有用的內容與正確技術設定；不建立 `llms.txt`、AI 專用 schema 或任何無法驗證的聲稱。
- 結構化資料僅使用符合頁面可見內容的類型與欄位；不能為了搜尋結果功能而虛構評價、價格、營業時間或服務範圍。
- 既有網站的發布仍遵循：本機預覽與人工核准 → 客戶自己的 GitHub 私有庫 Commit／Push → Cloudflare Git 自動建置 → 正式網址驗證。禁止直接部署。

## 交付模式

### 盤點模式

在不修改檔案的情況下，輸出：現況證據、P0／P1／P2 缺漏、內容待確認清單、建議的搜尋問題對應頁面，以及可執行的本機更新計畫。

### 更新模式

只有使用者核准更新清單後才執行。完成可核對的內容與技術更新後，執行適當的建置／檢查與本機預覽；清楚列出修改檔案、驗收結果與仍待客戶補齊的資訊。

### 發布模式

只有使用者明確說明可發布時，才讀取原專案的發布規範並逐一驗證 GitHub 與 Cloudflare 的發布硬閘門。
