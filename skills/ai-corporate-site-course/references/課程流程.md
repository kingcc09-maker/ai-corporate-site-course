# 課程流程

## 交付成果

- Astro 靜態企業網站。
- 品牌資料收集表、內容架構、設計確認稿與核准紀錄。
- GitHub 私有儲存庫（以 GitHub Desktop 操作）。
- Cloudflare Workers 免費部署與暫用網址。
- 選配：正式網域與 `www` 的驗證紀錄。
- 課程講義交付時，一併提供可直接貼入 NotebookLM 生成簡報的提示詞。

## 建議順序

```text
收集客戶資料 → 盤點缺漏與訪談 → 網站架構與設計確認稿 → 客戶確認
→ SEO／AI 搜尋內容規劃 → 建立 Astro 網站 → 本機預覽與 SEO 驗收 → 客戶確認 → GitHub Desktop Commit / Push
→ Cloudflare 自動建置 → 暫用網址驗證 → 正式網域設定與驗證
```

## SEO 與 AI 搜尋可見度

每個企業形象網站預設建立「搜尋問題 → 對應頁面 → CTA」內容地圖，並在本機完成 title、description、主標題、網址、圖片 alt、內部連結、canonical、sitemap、robots、社群分享 metadata 與如實 JSON-LD 的驗收。上線後由客戶驗證 Search Console 並提交 sitemap。

AI 搜尋可見度沿用同一套人本、可讀、可驗證的 SEO 基礎；不保證排名、收錄或被 AI 摘要引用，也不需要 `llms.txt` 或 AI 專用 schema。

## 技術邊界

純形象網站、服務介紹、FAQ、案例和外部表單不需要資料庫。只有會員、訂單、預約時段、即時庫存、多人後台或大量可搜尋資料時，才另外規劃後端與資料庫。

## 本機驗收重點

檢查首頁、關於、服務、FAQ、聯絡頁；並測試導覽、圖片、CTA、電話、Email、LINE、表單、地圖以及手機版。若本機尚未通過，不能進入發布。
