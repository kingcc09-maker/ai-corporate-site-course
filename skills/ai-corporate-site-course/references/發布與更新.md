# 發布與更新

## 發布硬閘門

使用者提出「公開網站」「上線」或「部署」時，必須先回報下列狀態；不得略過任一項直接部署：

| 關卡 | 必須可驗證的結果 |
| --- | --- |
| 1. 本機核准 | 網站可本機預覽、檢查通過，且使用者確認可發布。 |
| 2. 客戶 GitHub 私有庫 | repository 屬於客戶／學員自己的 GitHub 帳號，並維持 Private。 |
| 3. Commit 與 Push | GitHub Desktop 已 Commit、Push，GitHub 網頁可看到最新 Commit。 |
| 4. Cloudflare Git 連線 | Cloudflare 連接正確的私有 repository 與 `main`，由 Git Push 自動觸發建置。 |

任何關卡未完成時，只協助完成該關卡；**不得**改以手動上傳、`wrangler deploy` 或直接部署至暫用網址取代。

## GitHub Desktop 操作

學員只需理解：

```text
本機確認 → Commit（留下版本）→ Push origin（備份並觸發發布）
```

Repository 應為客戶自己的私有庫。Commit 說明應能辨識變更，例如「更新服務內容與聯絡頁」。

## Cloudflare 部署

透過 GitHub repository 連線設定：生產分支 `main`、建置命令 `npm run build`、部署命令依 Cloudflare 專案類型設定。只允許由最新 GitHub Push 觸發建置。先驗證 `workers.dev` 暫用網址，再設定正式網域。

## 正式網域

在 Cloudflare 啟用網域後，新增 Worker 的根網域。設定 `www` 前先盤點既有 DNS；舊 A 或 CNAME 若仍指向原主機，必須先確認舊服務可停用，再移除或更新，避免 522、舊新網站混用或郵件紀錄受影響。

## 發布後

用正式網址驗證首頁與重點頁面。記錄發布日期、內容、核准人與可回復的上一版 Commit。
