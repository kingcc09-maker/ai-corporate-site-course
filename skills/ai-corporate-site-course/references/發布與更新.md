# 發布與更新

## 發布硬閘門

使用者提出「公開網站」「上線」或「部署」時，必須先回報下列狀態；不得略過任一項直接部署：

| 關卡 | 必須可驗證的結果 |
| --- | --- |
| 1. 本機核准 | 網站可本機預覽、檢查通過，且使用者確認可發布。 |
| 2. 客戶 GitHub 私有庫 | repository 屬於客戶／學員自己的 GitHub 帳號，並維持 Private。 |
| 3. Commit 與 Push | GitHub Desktop 已 Commit、Push，GitHub 網頁可看到最新 Commit。 |
| 4. Cloudflare Git 連線 | Cloudflare 連接正確的私有 repository 與 `main`，由 Git Push 自動觸發建置。 |

任何關卡未完成時，只協助完成該關卡；**不得**改以手動上傳、`wrangler deploy` 或直接部署至暫用網址取代。

## GitHub Desktop 前置檢查

GitHub 是客戶網站的私有版本備份庫，也是 Cloudflare 自動建置的來源；**不能移除**。本課程選用 GitHub Desktop 只是為了讓學員不必使用命令列。

1. 先確認客戶電腦是否已安裝 GitHub Desktop。
2. 未安裝時，開啟 GitHub Desktop 官方下載頁，清楚說明它只用於將本機已核准的網站 Commit／Push 到客戶自己的私有 GitHub repository。
3. 經使用者同意後安裝，並由客戶登入自己的 GitHub 帳號。
4. 完成後才進入 GitHub 私有庫、Commit 與 Push 關卡。

若客戶電腦因權限政策不能安裝程式，需明確告知使用者，改以 GitHub 網頁的私有 repository 手動上傳流程；仍不可跳過 GitHub 備份與 Cloudflare Git 連線。

## 網頁引導方式

GitHub、Cloudflare、網域註冊商等後台常為英文介面。每次需要使用者動手時，建站者／Codex 必須：

1. 直接開啟正確服務與頁面，不要求使用者自行找選單。
2. 捲動至目標按鈕或輸入欄完整可見的位置；可行時將游標停在目標附近或做視覺標示。
3. 用中文說明：「目前頁面是什麼」、「請找哪一個英文文字」、「按下／輸入後會發生什麼」。
4. 在登入、密碼、驗證碼、授權、刪除、發布、DNS 變更等最終動作前停下，交由使用者按下或輸入。
5. 使用者完成後，重新檢查頁面上的成功結果，再帶往下一步。

範例：不要只說「到 Settings 設定」。應開啟 GitHub repository 的 Settings 頁，將畫面帶到 `Danger Zone` 或實際目標，並說明該按鈕的影響。

## GitHub Desktop 操作

學員只需理解：

```text
本機確認 → Commit（留下版本）→ Push origin（備份並觸發發布）
```

Repository 應為客戶自己的私有庫。Commit 說明應能辨識變更，例如「更新服務內容與聯絡頁」。

## Cloudflare 部署

透過 GitHub repository 連線設定：生產分支 `main`、建置命令 `npm run build`、部署命令依 Cloudflare 專案類型設定。只允許由最新 GitHub Push 觸發建置。先驗證 `workers.dev` 暫用網址，再設定正式網域。

## 正式網域

在 Cloudflare 啟用網域後，新增 Worker 的根網域。設定 `www` 前先盤點既有 DNS；舊 A 或 CNAME 若仍指向原主機，必須先確認舊服務可停用，再移除或更新，避免 522、舊新網站混用或郵件紀錄受影響。

## 發布後

用正式網址驗證首頁與重點頁面。記錄發布日期、內容、核准人與可回復的上一版 Commit。
