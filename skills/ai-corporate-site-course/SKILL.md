# AI 企業網站建置課程

協助學員用已驗證的標準流程建立企業形象網站。這是教學與建站流程 skill，不用於需要會員、訂單、即時資料或後台多人編輯的系統型網站；那些需求要先另外規劃資料庫與後端。

## 開始前

1. 先讀取 [`references/課程流程.md`](references/課程流程.md)。
2. 檢查工作區的 `AGENTS.md` 與既有專案；不覆蓋客戶既有檔案。
3. 確認本次任務屬於資料收集、設計確認、網站建立、本機驗收、備份／部署或網站更新。

## 不可省略的工作原則

- 每個客戶獨立專案、GitHub 私有儲存庫、Cloudflare 專案與網域帳戶；建站者僅以協作者身分加入。
- 課程教材庫與客戶網站庫分開管理。公開課程教材可由 Codex 一鍵安裝；學員建立客戶網站時使用自己的 GitHub 帳號，不得共用講師或其他學員帳號。
- 所有內容先有資料來源與公開授權。不得編造案例、數據、合作品牌、證照、法規結論或聯絡資料。
- 先產出平面設計確認稿，再開始寫網站。設計稿要能檢核區塊、色彩、字體、字級、圖片方向及手機版差異。
- 標準發布流程是：**本機預覽與人工核准 → GitHub 備份 → Cloudflare 部署 → 正式網址驗證**。
- 未得到明確發布同意前，只能修改本機版本；不可 commit、push 或公開部署。
- 使用者說「公開網站」、「上線」、「部署」或同義詞時，一律視為啟動**發布硬閘門**，不是直接部署的指令。必須先逐項確認：本機驗收通過與核准、客戶自己的 GitHub 私有庫已建立、最新 Commit 已 Push 並可在 GitHub 看見、Cloudflare 已連接該 repository 的 `main` 分支。任一項未完成時，停止在該項並協助完成，絕不可跳過 GitHub 或直接上傳至 Cloudflare。
- Cloudflare 必須以 GitHub repository 自動建置與部署；不可把手動上傳、`wrangler deploy` 或暫用網址部署當成正式發布的替代流程。僅在 GitHub Push 成功後，才可觸發或等候 Cloudflare 建置。
- 本課程的預設 GitHub 操作工具是 **GitHub Desktop**，用來避免學員使用命令列。開始備份／部署前先檢查它是否已安裝與登入客戶自己的 GitHub 帳號；未安裝時，先開啟官方下載頁、以中文說明安裝用途並在使用者同意後安裝。不可因為缺少 GitHub Desktop 而移除 GitHub 私有庫或 Cloudflare Git 自動建置流程。
- 遇到 GitHub、Cloudflare、網域註冊商或 Google 等英文介面，不能只用文字交代路徑。必須先開啟正確頁面、捲到目標按鈕或輸入欄清楚可見的位置，並以中文指出畫面上的英文名稱、用途與下一步。若工具支援，將游標停在目標附近或以視覺標示協助定位；若不支援，提供目前畫面與目標控制項的明確中文對照。
- 任何需要使用者登入、輸入敏感資料或按下最終確認的步驟，都要停在該控制項前交給使用者操作；使用者完成後再檢查結果並帶往下一頁。
- 形象網站優先使用 Astro 與 Markdown／JSON。表單優先使用客戶自己的 Google Forms；不把密碼、金鑰或個資寫入原始碼。

## 各階段路由

### 資料收集

讀取 [`references/客戶資料收集表.md`](references/客戶資料收集表.md)。整理已知資料、缺漏、上線前必填欄位與訪談問題。客戶尚未提供的內容必須標記待補，不得以 AI 補造。

產業別導向的競品研究與問題樹是下一版模組；使用者要求時，先確認產業、服務地區、主要客群與可比較的同業範圍，再進行有來源的研究。

### 設計確認

讀取 [`references/提示詞庫.md`](references/提示詞庫.md) 的「設計確認」提示詞。先交付可核准的設計規格／平面稿說明，等使用者確認後才進入建置。

### 網站建立與本機驗收

採 Astro 靜態網站。內容結構採 Markdown／JSON，保留既有專案慣例。完成後做可用的檢查、建置與本機頁面驗收，但不發布。

### 備份與發布

讀取 [`references/發布與更新.md`](references/發布與更新.md)。教學優先採 GitHub Desktop，不要求學員使用命令列。先確認 GitHub Desktop 已安裝與登入，再列出發布硬閘門的四項狀態並取得本次發布的明確同意，再依序完成 GitHub 私有庫、Commit／Push 驗證、Cloudflare Git 連線、暫用網址驗證與正式網域驗證。任何 GitHub、Cloudflare、網域或 DNS 的變更，都要在執行前明確說明影響，且僅在使用者已核准該步驟時操作。

在每個需要使用者確認的網頁步驟，依「網頁引導」方式協助定位，不要只輸出英文選單路徑。

## 對話方式

使用繁體中文、非技術性語言。每個階段先說明交付物與待確認項目。若需要資料庫，先說明它解決的具體需求，以及靜態網站為何不足。
