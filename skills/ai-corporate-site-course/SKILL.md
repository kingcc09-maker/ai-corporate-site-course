# AI 企業網站建置課程

協助學員用已驗證的標準流程建立企業形象網站。這是教學與建站流程 skill，不用於需要會員、訂單、即時資料或後台多人編輯的系統型網站；那些需求要先另外規劃資料庫與後端。

## 開始前

1. 先讀取 [`references/課程流程.md`](references/課程流程.md)。
2. 檢查工作區的 `AGENTS.md` 與既有專案；不覆蓋客戶既有檔案。
3. 確認本次任務屬於資料收集、設計確認、網站建立、本機驗收、備份／部署或網站更新。

## 不可省略的工作原則

- 每個客戶獨立專案、GitHub 私有儲存庫、Cloudflare 專案與網域帳戶；建站者僅以協作者身分加入。
- 所有內容先有資料來源與公開授權。不得編造案例、數據、合作品牌、證照、法規結論或聯絡資料。
- 先產出平面設計確認稿，再開始寫網站。設計稿要能檢核區塊、色彩、字體、字級、圖片方向及手機版差異。
- 標準發布流程是：**本機預覽與人工核准 → GitHub 備份 → Cloudflare 部署 → 正式網址驗證**。
- 未得到明確發布同意前，只能修改本機版本；不可 commit、push 或公開部署。
- 形象網站優先使用 Astro 與 Markdown／JSON。表單優先使用客戶自己的 Google Forms；不把密碼、金鑰或個資寫入原始碼。

## 各階段路由

### 資料收集

讀取 [`references/客戶資料收集表.md`](references/客戶資料收集表.md)。整理已知資料、缺漏、上線前必填欄位與訪談問題。客戶尚未提供的內容必須標記待補，不得以 AI 補造。

產業別導向的競品研究與問題樹是下一版模組；使用者要求時，先確認產業、服務地區、主要客群與可比較的同業範圍，再進行有來源的研究。

### 設計確認

讀取 [`references/提示詞庫.md`](references/提示詞庫.md) 的「設計確認」提示詞。先交付可核准的設計規格／平面稿說明，等使用者確認後才進入建置。

### 網站建立與本機驗收

採 Astro 靜態網站。內容結構採 Markdown／JSON，保留既有專案慣例。完成後做可用的檢查、建置與本機頁面驗收，但不發布。

### 備份與發布

讀取 [`references/發布與更新.md`](references/發布與更新.md)。教學優先採 GitHub Desktop，不要求學員使用命令列。任何 GitHub、Cloudflare、網域或 DNS 的變更，都要在執行前明確說明影響，且僅在使用者已核准該步驟時操作。

## 對話方式

使用繁體中文、非技術性語言。每個階段先說明交付物與待確認項目。若需要資料庫，先說明它解決的具體需求，以及靜態網站為何不足。
